# 目录与文件规范

[返回首页](../README.md) · [提交说明](../CONTRIBUTING.md)

## 每一层负责什么

| 层级 | 放什么 | 说明 |
| --- | --- | --- |
| 仓库根目录 | 各实验入口与维护说明 | 不在首页重复整份实验报告 |
| labN/README.md | 该实验任务、环境、运行、结果和限制 | 先给报告、代码和证据入口 |
| 代码目录 | 可编译的完整包与构建配置 | 源码、launch、配置等保持一起 |
| 报告目录 | 中英文报告、理论题与排版源稿 | 标出当前阅读入口 |
| 原始证据目录 | 截图、视频、bag与当轮参数 | 按实际运行保留 |
| 分析目录 | CSV、指标和统计图 | 说明计算方法和来源 |
| 脚本目录 | 构建、运行、复算和生成工具 | 写清输入、输出和使用环境 |

## 现有路径怎么对应

| 资料类别 | Lab1 / Lab2 | Lab3 / Lab4 | Lab5 |
| --- | --- | --- | --- |
| 报告 | report或Lab2根目录 | deliverables | deliverables |
| 源码 | lab1_demo、RandomVector、two_drones_pkg | code | feature_tracking |
| 截图 | report/figures或images | data/raw/screenshots | screenshots |
| 分析 | 报告中的练习结果 | data/analysis | results与charts |
| 操作工具 | CMake与ROS launch | review/scripts | scripts |

这些不同名称来自各实验原项目。新增说明统一导航，既有ROS包和构建路径继续沿用，避免移动后让launch、脚本和旧报告链接失效。

## 文件怎样命名

- 新截图使用两位序号、方法和内容，例如`06_SIFT_RANSAC.png`。索引必须说明其对应的报告图号。
- 中英文报告在同一索引列出，英文文件名使用`EN`区分。已经被报告和文档引用的旧文件名不随意改动。
- 新一轮数据按`run_日期_时间`单独保存，参数、日志与记录放在同一轮目录。
- 新的统计图应注明输入数据和计算口径；不能只留一张没有来源的图片。

## 构建产物与历史记录

新的build、devel、install、Python缓存等由根目录.gitignore排除。Lab1中已有的build与可执行文件是历史归档，仍可查看，但不作为跨机器运行所需源码。复现时应重新生成构建目录。

## 修改后的基本检查

```bash
python tools/check_navigation.py
git diff --check
```

链接检查只核对仓库内相对路径是否存在，不替代PDF排版检查、算法验证或外部网站可用性检查。
