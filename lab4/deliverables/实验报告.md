### 2.1 轨迹与控制实现

代码按四个Part补全，具体内容见表2。核心实现位于simple_traj_planner.cpp和trajectory_generation_node.cpp。

表2 各部分实现及设计理由

| **部分** | **实现内容** | **设计理由** |
| --- | --- | --- |
| Part0 | 第一门设为固定目标，期望速度和加速度设为0 | 在连续飞行前确认坐标与控制链路 |
| Part1.1 | 读取当前位置和yaw，确认数值有效 | 避免从未初始化的状态规划 |
| Part1.2 | 添加起点与赛门约束，分别优化位置和yaw | 满足目标并协调转向 |
| Part1.3 | 按经过时间采样，发布位置、速度、加速度和朝向 | 将整条轨迹转为控制器可执行的当前目标 |

Yaw是从上方看机头的朝向角，相当于无人机的“指南针方向”。它跨过±180°时会发生数值跳变，例如179°到-179°只需转2°。代码用atan2(sin Δψ, cos Δψ)选择相邻目标间的短角度变化，再累加为连续朝向，避免把2°误认为358°。

位置轨迹有三个分量，朝向只有一个分量，二者分别求解，但共用分段时间。因此到达某道门时，位置和机头朝向对应同一时刻。起点使用实际状态，起终点通过makeStartOrEnd设置边界条件；内部航点固定目标位置与yaw。滚转、俯仰由控制器根据运动需求调整，不单独指定完整路线。

Minimum snap指最小化位置四阶导数的平方积分，以减少参考轨迹过于猛烈的变化。代码先估计各段时间，再乘时间倍率，随后在线性优化器中求出多项式系数。这里优化的是参考轨迹，不直接保证旋翼能耗最小，也不包含障碍物在线重规划。[3]

每次发布时，采样时间取“当前ROS时间减轨迹开始时间”，并限制在0到总时长之间。目标位姿写入transforms，线速度和线加速度分别写入velocities、accelerations。Yaw转换为四元数，即用四个数表示三维方向。到达结束时刻后保持末端目标。本次沿用Lab3的简化控制器，没有加入期望角速度前馈，即没有提前补偿目标转向速度。

### 2.3 数据记录与处理

用于分析的是run_20261022_000059。Bag是按时间保存ROS消息的文件。本记录包含40534条消息，其中实际状态8365条、期望状态7836条，还保留了仿真时钟、赛门目标与旋翼命令。

![图5 记录文件与bag话题检查；实际与期望状态均已保存（原截图08）](../data/raw/screenshots/08_完整通关rosbag检查_记录时长与状态话题消息数量.png)

两类状态的消息数量不同，不能按数组下标直接相减。本次使用bag记录时间，将期望位置线性插值到实际状态时刻；也就是用相邻两个目标值估计中间时刻的目标。Yaw先展开再插值。利用持续推进阶段的“记录时间减轨迹经过时间”估计轨迹起点，并排除结束后的保持阶段，得到6708个执行段样本。

位置误差定义为实际位置减期望位置。三维RMSE（均方根误差）为sqrt(mean(ex²+ey²+ez²))，它综合各采样点偏差，并对较大的误差赋予更高权重。各轴平均有符号误差用来区分持续偏移与正负波动。[4]

### 2.4 为什么这样设计

轨迹生成前先拿到实际起点，是为了避免无人机从默认坐标突然跳到一条不属于当前位置的路线。固定目标测试通过后，才把目标换成随时间推进的轨迹。表4把几个容易混淆的选择放在一起。

表4 关键设计与原因

| **选择** | **为什么这样做** | **本次边界** |
| --- | --- | --- |
| 实际位置与yaw作起点 | 起点和当前状态一致，减少参考突变 | 仍需等待有效状态；不是任意状态下都能立即起飞 |
| 位置与yaw分别优化、共用时间 | 到门时，位置与朝向目标同步 | 不单独规划完整滚转和俯仰曲线 |
| 时间倍率2.0 | 给跟踪留出更多执行时间 | 未做其他倍率的实测对比 |
| 只在首次有效航点到达后求解 | 重复收到赛门时不重置路线 | 重跑必须重启跟随节点 |
| 末端时间截断 | 不在轨迹范围外取值，到终点后保持 | 轨迹结束不等于关闭控制器 |

对同一条曲线，如果只是把执行时间拉长两倍，速度会减为一半，加速度会减为四分之一。这能解释为什么时间分配会影响跟踪难度。但本次没有另一倍率的对照运行，不能把这个时间缩放关系写成实测提升。

## 4 讨论

这轮能飞完整条路线，但“跟得准”“为什么有误差”和“跑得快”是不同问题。下面分别讨论。

### 4.1 跟踪效果与高度偏差

水平方向RMSE分别约0.72cm和0.64cm，明显小于Z方向的5.56cm。Z方向平均误差为-5.47cm，与该方向RMSE接近，说明高度误差含有持续向下的偏移，而不仅是正负随机波动。首门悬停也出现高度偏低，但单点读数与完整执行段属于不同统计口径，不能用两者的差值推断偏差随时间增长。

本记录中95%分位误差约6.81cm，最大约8.44cm，可与平均误差一起描述这一轮的跟踪分布。它们不能用于推断其他参数、其他路线或真实无人机的表现。现有数据没有对控制参数和模型项逐一做隔离实验，因此无法确定高度偏差的具体原因。

### 4.2 轨迹优化与理论结果的关系

单段理论题把时间与位移固定，再最小化速度平方积分。平方会放大速度峰值，因此原始位置约束下匀速最优；这只是题目选定的代价，不等于无人机耗电。当只有P(0)=0、P(1)=1时，最优P(t)=t，增加到二次或三次不会降低代价J=1。加上P'(1)=-2后，二次解为4t-3t²，J=4；三次解为t/4+9t²/2-15t³/4，J=17/8。这个对比说明，多项式次数只有在新增自由度能满足约束并改善目标时才有作用。

多段最小snap理论在一维、分段时间固定、航点位置已知且起终点低阶导数固定的条件下，每段可用七次多项式表示。k段共有8k个系数：位置条件2k个，起终点导数条件6个，内部低阶连续条件3(k-1)个，自然最优条件3(k-1)个。自然条件来自求最优解，不能全部当成外加约束。例如三段共有24个系数，显式约束18个，自然条件6个。

代码使用N=10，即每段10个系数、最高九次；它与上述七次理论的边界设置和实现选择不同，不能把N直接改成7。两份个人理论题已分别整理为英文deliverable_1.pdf和deliverable_2.pdf，保留矩阵、求解和代回检查。

### 4.3 数据与实验方法的局限

误差相对于仿真发布的实际状态计算，并非外部测量系统验证的定位误差。记录时间对齐不能完全分离通信延迟与控制误差。全重叠时段RMSE为0.054428m，因包含末端保持而与执行段不同，本报告主要采用后者。记录中未发现时钟回退，但这并不消除其他采样与通信影响。

静态截图只能说明某一时刻的状态；到赛门中心的最近距离也不能独立证明正确穿门。完整通关判断依靠连续视频和本人运行检查，数值分析用于补充跟踪表现。采样点累计路径长度同样不是精确赛道几何长度。

本次只有一轮完整材料，也没有独立裁判计时，因此134.17s仅称为参考轨迹时长。时间倍率2.0给跟踪留下了更多时间，但没有倍率1.0或其他设置的对照，不能量化其改善幅度。

### 4.4 调试经验与后续工作

环境准备时，gflags_catkin缺失通过补齐源码解决；catkin_simple指向旧目录的问题通过备份旧build/devel后重建解决；NLopt下载连接被拒绝后，改用校验过的本地安装包，最终20个包全部编译成功。第一次录制无法找到/desired_state，确认话题就绪后第二次正常保存。这些问题分别属于依赖、缓存、下载与启动时序，需要按错误所在环节处理。

后续可先固定路线与时间倍率，每次只改变一个控制或模型参数，比较高度平均偏差、最大误差和通关情况。稳定后再逐步缩短分段时间，并用多轮结果比较成功率和用时。本报告没有将这些计划写成已完成的实验。

### 4.5 把高度误差再拆开看

只看三维RMSE，很难判断是水平偏差还是高度偏差。用各轴RMSE可进一步计算水平合成误差；再把Z方向均方误差拆成平均偏移平方与去均值波动两部分。

表9 从原统计量得到的补充诊断

| **诊断量** | **结果** | **计算与含义** |
| --- | --- | --- |
| 水平合成RMSE | 0.96cm | sqrt(RMSE_X²+RMSE_Y²)，合并X与Y |
| 高度占三维均方误差的比例 | 97.10% | RMSE_Z² / RMSE_3D²，说明高度是主要误差方向 |
| 平均偏移平方占Z均方误差比例 | 96.68% | mean(eZ)² / mean(eZ²)，说明持续偏移占主导 |
| 高度去均值后的均方根波动 | 1.01cm | sqrt(mean(eZ²)-mean(eZ)²)，描述围绕平均偏差的变化 |

这些数值只是对同一轮记录的重新分解，不是新增实验。均方误差按各轴相加，RMSE本身不能直接相加。偏移占比高，也不意味着可以直接把目标高度抬高相同数值作为通用修复；那样可能只遮住现象，无法验证原因。

### 4.6 怎样安排下一轮验证

后续应把“检查原因”和“争取更快”分开。先保证同一设置能重复完成，再改变一个因素，避免同时改多个参数后无法判断是哪一项起作用。

## 5 结论

四个Part已经接通：固定目标悬停、读取实际起点、规划位置和朝向、按时间发送目标。保存的一轮运行完成了赛道，执行段三维位置RMSE为5.64cm，最大误差为8.44cm。水平误差小，高度持续偏低；现有记录还不能确定原因。

mav_trajectory_generation::Vertex start_yaw(1), end_yaw(1);

yaw_vertices.push_back(start_yaw);
double last_yaw = current_yaw;
// 逐门添加位置和朝向；同一索引对应同一门。
for (auto i = 0; i < poseArray.poses.size(); ++i) {
// 读取当前索引对应的赛门位姿。
  const auto& pose = poseArray.poses[i];
  Eigen::Vector3d position(pose.position.x, pose.position.y, pose.position.z);
  mav_trajectory_generation::Vertex vertex(D);
// 最后一道门使用终点边界；中间门仅固定目标值。
  if (i + 1 == poseArray.poses.size())
    vertex.makeStartOrEnd(position, SNAP);
  else
    vertex.addConstraint(POSITION, position);
  vertices.push_back(vertex);
  double yaw = tf::getYaw(pose.orientation);
// 短角差累加：处理±π跨界，防止绕远转向。
  yaw = last_yaw + std::atan2(std::sin(yaw - last_yaw), std::cos(yaw - last_yaw));
  mav_trajectory_generation::Vertex yaw_vertex(1);
  Eigen::VectorXd yaw_value(1);
  yaw_value << yaw;
// 最后一道门使用终点边界；中间门仅固定目标值。
  if (i + 1 == poseArray.poses.size())
    yaw_vertex.makeStartOrEnd(yaw_value, SNAP);
  else
    yaw_vertex.addConstraint(ORIENTATION, yaw);
  yaw_vertices.push_back(yaw_vertex);
  last_yaw = yaw;
