## A 新环境第一次准备

下表只适用于已经装好Ubuntu20.04和ROS Noetic的新工作空间。ROS是连接程序的消息框架；catkin是它的编译工具。

| **步骤** | **命令 / 操作** | **说明** |
| --- | --- | --- |
| 获取代码 | git clone --depth 1 --filter=blob:none --sparse https://github.com/hbyhby123/vnav-personal.git ~/vnav_lab4_source | 指定目录已存在时先检查，不重复克隆 |
| 只取运行资料 | git -C ~/vnav_lab4_source sparse-checkout set lab4/code lab4/review | 不下载视频分片，节省网络 |
| 建工作空间 | mkdir -p ~/vnav_ws/src | 现有工作空间先备份三个包 |
| 复制最终包 | cp -a ~/vnav_lab4_source/lab4/code/controller_pkg ~/vnav_lab4_source/lab4/code/planner_pkg ~/vnav_lab4_source/lab4/code/trajectory_generation_pkg ~/vnav_ws/src/ | 新环境直接复制；已有修改不要盲目覆盖 |
| 配依赖并构建 | bash ~/vnav_lab4_source/lab4/review/scripts/setup_dependencies.sh | 安装系统依赖、bridge、gflags_catkin，并修复NLopt下载；需要网络和sudo |
| 模拟器 | 下载https://vnav.mit.edu/material/lab4.zip并解压到~/vnav-builds | 失败时使用官方README的Google Drive模拟器目录 |
| 识别场景 | python3 ~/vnav_lab4_source/lab4/review/scripts/find_simulator.py | 保存~/lab4_evidence/sim.env |

已经有Lab4依赖、只需恢复归档程序时，可运行review/scripts/install_lab4.sh。它会备份现有三包，复制归档版本并构建。完整ROS和模拟器均不在本仓库中。

## B 所有窗口关闭后的启动顺序

每个编号都用Ctrl+Alt+T新开终端，保持运行。不同时启动旧Lab3圆轨迹节点。

### 终端1 模拟器

```bash
source ~/lab4_evidence/sim.env
cd "$(dirname "$SIM_EXEC")"
"$SIM_EXEC"
```

点击Unity画面按R复位。仿真器就是提供赛道和无人机物理运动的程序。

### 终端2 桥接

```bash
source /opt/ros/noetic/setup.bash
source ~/vnav_ws/devel/setup.bash
roslaunch tesse_ros_bridge tesse_quadrotor_bridge.launch
```

桥接相当于翻译员，把Unity状态送给ROS，再把旋翼命令送回Unity。

### 终端3 可选先演示首门悬停

```bash
source /opt/ros/noetic/setup.bash
source ~/vnav_ws/devel/setup.bash
source ~/lab4_evidence/sim.env
roslaunch planner_pkg static_point_test.launch simulator_data_directory:="$SIM_DATA" kx:=2 kv:=3 kr:=3 komega:=1
```

稳定后演示当前位置，再Ctrl+C关闭该测试。点击Unity按R复位，然后在终端3启动完整跟随器：

```bash
roslaunch trajectory_generation traj_following.launch kx:=2 kv:=3 kr:=3 komega:=1 time_scale:=2.0
```

### 终端4 录像并录数据

```bash
mkdir -p ~/lab4_evidence
wget -O ~/lab4_evidence/record_race.sh https://raw.githubusercontent.com/hbyhby123/vnav-personal/master/lab4/review/scripts/record_race.sh
bash ~/lab4_evidence/record_race.sh
```

录屏前有5秒准备，摆好Unity画面，不改变桌面分辨率。看到Video and bag recording后才触发航点。此脚本依赖Xorg桌面、ffmpeg和已运行的ROS节点；源码安装、飞行和录制是不同步骤。

### 终端5 最后发布赛门

```bash
source /opt/ros/noetic/setup.bash
source ~/vnav_ws/devel/setup.bash
source ~/lab4_evidence/sim.env
roslaunch planner_pkg traj_gen.launch simulator_data_directory:="$SIM_DATA"
```

切回Unity观察全程。通过最后一门后等3秒，回终端4按Enter，等待保存完成。每轮自动保存到~/lab4_evidence/runs/run_日期时间。新一轮先停终端5、再停终端3、Unity按R，然后按“跟随→记录→航点”重启。

## C 检查状态与保存材料

```bash
source /opt/ros/noetic/setup.bash
source ~/vnav_ws/devel/setup.bash
rostopic echo -n 1 /desired_state/transforms
rostopic echo -n 1 /current_state/pose/pose/position
rostopic info /desired_state
```

| **要检查什么** | **通过标准** |
| --- | --- |
| 首门目标 | 期望与实际位置接近，能稳定保持 |
| 发布者 | /desired_state只有当前测试需要的一套目标节点 |
| 视频 | 从出发前到最后一门后连续清晰，不能拼接多次成功 |
| bag | 含/current_state与/desired_state，非零消息，覆盖完整运行 |
| 保存 | 正常Ctrl+C或Enter结束，不留下.bag.active |
| 计时 | 134.17秒是本轮参考轨迹时长；bag总长167.28秒不是竞速成绩 |

## E 已遇到的故障

| **现象** | **原因与处理** |
| --- | --- |
| gflags_catkin找不到 | 它是缺少的源码依赖，不是仅装libgflags-dev就完成；运行repair_dependencies.sh |
| catkin_simple指向旧src路径 | 依赖目录移动后残留编译缓存，备份build/devel后重建 |
| nlopt连接被拒绝 | 旧下载链路失败，repair_nlopt.sh下载原始2.4.2归档、校验后让构建读取本地缓存 |
| Unknown topic /desired_state | 当时目标节点不可用或正在切换；先启动跟随器，确认rostopic info成功，再录制；本轮第二次记录成功 |
| wget提示416 | 文件已经完整下载；随后解压和路径识别成功时不属于下载失败 |
| 不认识Desktop | Ubuntu路径区分大小写，桌面是~/Desktop |
| 只按R后没有重跑 | 旧轨迹仍保留；停止航点和跟随器，再复位重启 |
